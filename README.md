# Image Aspect Ratio（图片比例判断节点）

根据图片宽高，判断最接近哪个常用比例（1:1 / 2:3 / 3:2 / 3:4 / 4:3 / 5:4 / 4:5 / 9:16 / 16:9 / 9:21 / 21:9 / 1:2 / 2:1），
并输出该比例对应的标准尺寸（宽、高）。

## 1. 安装节点

⚠️ ComfyUI 对「文件夹形式」的插件**只认 `__init__.py`**，不会去扫描文件夹里的
`.py` 文件。所以文件夹里必须同时有 `__init__.py`，否则日志会报
`FileNotFoundError: ...__init__.py` 和 `IMPORT FAILED`，节点在画布上显示为**红框**、
输入框显示 `UNKNOWN`。

正确结构（两个文件都要）：

```
ComfyUI/custom_nodes/aspect_ratio/
├── __init__.py                     # 必须有
└── image_aspect_ratio.py
```

`__init__.py` 内容：

```python
from .image_aspect_ratio import NODE_CLASS_MAPPINGS, NODE_DISPLAY_NAME_MAPPINGS

__all__ = ["NODE_CLASS_MAPPINGS", "NODE_DISPLAY_NAME_MAPPINGS"]
```

更简单的替代方案：把 `image_aspect_ratio.py` 单独丢进 `ComfyUI/custom_nodes/`
根目录（不建子文件夹），也会被正常加载。

放好后**重启 ComfyUI**。之后在节点列表 `utils/aspect` 分类下会看到
`Image Aspect Ratio` 节点。

## 2. 使用

- **输入 `image`**（IMAGE，可选）：连接任意图片输出，自动读取宽高。
- **输入 `width` / `height`**（INT，可选）：不连图片时，直接填数值判断。
  如果两者都填了非 0 值，优先使用这里填的数字。
- **输出 `ratio`**（STRING）：判断结果，如 `"2:3"`。
- **输出 `target_width` / `target_height`**（INT）：该比例的标准尺寸，
  可直接连到 `EmptyLatentImage` 等节点。

## 3. 合并进你自己的工作流

1. 在 ComfyUI 里打开 `aspect_ratio_demo.json`；
2. 选中 `Image Aspect Ratio` 节点（需要的话连 `EmptyLatentImage` 一起选），`Ctrl+C`；
3. 切到你自己的工作流标签页，`Ctrl+V` 粘贴；
4. 把你已有的图片输出连到这个节点的 `image` 输入即可。

## 4. 标准尺寸：一律用精确比例（不用习惯尺寸）

**原则：以数学计算为准，不以习惯叫法为准。**

判断用精确比例（1/1、2/3、3/4…），`STANDARD_SIZE` 也用精确比例，
两边完全自洽。刻意**不用** SDXL 那套习惯尺寸，因为它们并不是精确比例：

| 尺寸 | SDXL 习惯叫法 | 实际是 | 本节点判断 |
|---|---|---|---|
| `896×1152` | 3:4 | 7:9 = 0.7778 | **4:5**（0.8 比 0.75 更近） |
| `832×1216` | 2:3 | 13:19 = 0.6842 | 2:3 |
| `768×1344` | 9:16 | 4:7 = 0.5714 | 9:16 |

（若沿用习惯尺寸，会出现「判为 3:4 却输出 896×1152，而 896×1152 又判成 4:5」的自相矛盾。）

现在的精确尺寸表（宽高严格等于该比例，且都是 64 的倍数）：

| 比例 | 标准尺寸 | 实际比值 |
|---|---|---|
| 1:1 | 1024 × 1024 | 1.0000 |
| 2:3 | 768 × 1152 | 0.6667 |
| 3:2 | 1152 × 768 | 1.5000 |
| 3:4 | 768 × 1024 | 0.7500 |
| 4:3 | 1024 × 768 | 1.3333 |
| 5:4 | 1280 × 1024 | 1.2500 |
| 4:5 | 1024 × 1280 | 0.8000 |
| 9:16 | 576 × 1024 | 0.5625 |
| 16:9 | 1024 × 576 | 1.7778 |
| 9:21 | 576 × 1344 | 0.4286 |
| 21:9 | 1344 × 576 | 2.3333 |
| 1:2 | 704 × 1408 | 0.5000 |
| 2:1 | 1408 × 704 | 2.0000 |

每种尺寸喂回节点都会判回它自己（`_verify_connect.py` 里有自洽性测试，全部通过）。

> **9:16 偏小的说明**：在「精确比例 + 64 倍数」两个约束下，9:16 只能取
> `576×1024`（下一档 `1152×2048` 是 2.36MP，太大）。若嫌小，可把整张表
> 放宽到 16 倍数，9:16 即可用 `720×1280`，但需自行确认底模是否接受非 64 倍数。
> 用 SD1.5（512 基准）时，按同样规则整体缩小即可。
>
> **21:9 / 1:2 的说明**：21:9（=7:3）在 64 倍数约束下取 `1344×576`；
> 1:2 取 `704×1408`，均已接近 1MP。

## 5. 连不上第三方节点的「下拉框」输入？（已修复）

`ratio` 的输出类型是 `"*"`（Any，任意类型）而**不是** `"STRING"`，这是故意的。

像 `comfyui-Banana-API-3` 的 `aspect_ratio` 这种输入，声明形式是
`(["Auto", "1:1", "9:16", ...], {...})`，类型是 **COMBO（下拉框）**。
ComfyUI 后端 `comfy_execution/validation.py` 的校验逻辑是「两边类型必须有交集」，
而 `STRING` 与 `COMBO` 没有任何交集，所以 **STRING → COMBO 的连接会被拒绝**：

```
STRING -> COMBO : False   ❌ 被拒绝（报 Return type mismatch between linked nodes）
*      -> COMBO : True    ✅ 可连
```

改成 `"*"` 后前后端都放行。另外本节点输出的 13 个比例值
（1:1 / 2:3 / 3:2 / 3:4 / 4:3 / 5:4 / 4:5 / 9:16 / 16:9 / 9:21 / 21:9 / 1:2 / 2:1）
中，前 9 个**都在 Banana 插件的可选列表里**；后 4 个（9:21 / 21:9 / 1:2 / 2:1）
需确认目标下拉框是否收录，否则连接虽放行、运行时可能报「值非法」。

> 补充：如果你以后遇到别的「下拉框」输入连不上，通用解法就是把上游节点的
> 输出类型写成 `"*"`，而不是 `"STRING"`。
